# 测试 Skill

## 何时用

- 功能开发完成，准备提交。
- 发现 bug，需要先写失败用例再修。
- 演示前做回归。

## 铁律

1. **测试金字塔**：单元 ≫ 接口 > E2E。E2E 只覆盖主干，控制在 10 条以内。
2. **异常分支优先**：空数据、超时、越权、并发，这四类最容易线上出事。
3. **一个测试只断言一件事**；名字写清楚"给定…当…则…"。
4. **测试不依赖执行顺序和真实外网**（外部依赖用 mock/固定种子）。

## 测试分层与工具

| 层   | 工具                        | 覆盖                               | 目标比例 |
| ---- | --------------------------- | ---------------------------------- | -------- |
| 单元 | JUnit 5 / Vitest            | 纯函数、状态机、清洗规则、距离计算 | ~70%     |
| 接口 | MockMvc / Vitest+MSW        | Controller 参数校验、鉴权、错误码  | ~20%     |
| 集成 | Testcontainers / 本地 MySQL | 事务、SQL、迁移脚本                | ~5%      |
| E2E  | Playwright                  | 关键路径、闭环演示                 | ~5%      |

## 用例设计方法

- **等价类**：有效/无效各取代表值（如均价 0、负数、超上限）。
- **边界值**：半径 0/0.5/1/3/超大；分页第 1 页/最后 1 页/越界页。
- **状态迁移**：POI 状态机 `active→closed→reopened` 全路径。
- **正交组合**：筛选条件两两组合，别做笛卡尔积。

## 本项目必须覆盖的场景（清单）

- [ ] 清洗：缺坐标入隔离区；坐标转换误差 < 50m；品牌归一命中
- [ ] 去重：同 `source_ref` 二次执行不新增；同名同位置合并
- [ ] 距离：小区周边 1km 查询结果与独立脚本一致（误差 < 1%）
- [ ] 分页：翻页不重不漏；排序稳定
- [ ] 鉴权：普通用户调审核接口 403
- [ ] 反馈：低风险直接生效；高风险进审核；通过后主表与版本表同更新
- [ ] 闭环 B：提交"新增点位" → 生成任务 → 执行 → 地图可见
- [ ] 合规：未授权域名触发抓取被拒绝

## 步骤

1. 从需求编号出发列用例表（编号 → 场景 → 预期）。
2. 先写失败用例（红），再实现（绿），最后重构。
3. 跑全量 + 覆盖率，低于门槛补用例（不是补注释）。
4. E2E 用固定种子数据，避免测试互相干扰。

## 产出物清单（DoD）

- [ ] 用例表与需求编号一一对应
- [ ] 单元/接口测试全绿，核心模块覆盖率 ≥ 80%
- [ ] E2E 关键路径全绿
- [ ] 每个已修 bug 有回归用例
- [ ] 测试数据可重复生成（seed 脚本）

## 反模式

| 反模式           | 症状           | 修法                 |
| ---------------- | -------------- | -------------------- |
| 只测 happy path  | 上线炸在空数据 | 补异常四件套         |
| 测试之间共享状态 | 单跑过、全跑挂 | 每个用例独立造数     |
| 用 sleep 等异步  | 偶发失败       | 用 await/pollUntil   |
| 断言实现细节     | 重构就红       | 断言对外行为         |
| 覆盖率刷数字     | 全是 getter    | 盯分支覆盖，不盯行数 |
