# 系统设计 Skill

## 何时用

- SRS 已评审通过，准备开工。
- 要引入一个新组件（地图库、缓存、消息队列）之前。
- 有人问"为什么不直接用 XX"。

## 铁律

1. **每个技术选择都要能回答"不选另一个的理由"**，落在 ADR 里。
2. **先定契约，后写代码**。接口返回结构、错误码先冻结。
3. **数据模型优先**：表结构错了，后面全是返工。
4. **失败是常态**：每个外部依赖都要写超时、重试、降级。

## 步骤

### 1. 上下文图（C4-L1）

- 系统边界 + 外部依赖（高德 API、地图瓦片、用户、运营）。
- 标注每个依赖的：协议、鉴权方式、SLA/配额、失败后果。

### 2. 容器图（C4-L2）

- 前端 / 后端 API / 采集器 / 数据库 / 调度器。
- 每个容器写：职责一句话、技术栈、数据流向、部署形态。
- **避免过度拆分**：MVP 允许采集器与 API 同进程（模块化），但代码分层必须清晰。

### 3. 组件与分层（C4-L3）

- 后端建议分层：`controller → service → domain → repository`，采集侧独立 `crawler` 模块。
- 定义**适配器接口**：`PoiSourceAdapter { fetch(scope) → List<RawPoi> }`，新增数据源只实现接口。

### 4. 数据模型

- ER 图 + 建表 DDL（字段、类型、索引、约束）。
- 明确：主键策略、去重唯一键、软删除策略、版本表写法、归档策略。
- 空间查询方案必须写清算法与索引（如 bbox 粗筛 + Haversine 精算）。

### 5. 接口契约

- 统一响应：`{ code, message, data, traceId }`；错误码表（业务码 + HTTP 码）。
- 分页：`page/size` + `total`，或游标分页（说明选择理由）。
- 为每个接口写：方法、路径、鉴权、入参、出参示例、错误场景。

### 6. 关键时序

- 至少画 3 条：**采集任务执行**、**周边查询**、**反馈审核生效**。
- 标出事务边界、幂等点、缓存失效点。

### 7. 容量与性能设计

- 估算：数据量、QPS、单次查询扫描行数、索引命中。
- 给出前端的渲染策略：视口裁剪 / 聚合 / 分页上限。

### 8. 技术决策记录（ADR）

每条 ADR：`标题 / 状态 / 背景 / 选项 / 决策 / 后果`。
必写：后端框架、数据库、地图方案、鉴权方式、部署形态。

### 9. 评审

- 用 `verification` Skill 安排一个子代理做**对立面审查**：找漏洞、找过度设计、找遗漏的失败模式。

## 产出物清单（DoD）

- [ ] 架构图（上下文 + 容器 + 关键组件）
- [ ] ER 图 + 可执行 DDL
- [ ] 接口契约（OpenAPI 或 Markdown 表格）
- [ ] 3 条以上时序图
- [ ] ADR ≥ 5 条（含"为什么不选"）
- [ ] 容量估算与索引方案
- [ ] 设计评审记录（含被否掉的方案）

## 反模式

| 反模式       | 症状                     | 修法                    |
| ------------ | ------------------------ | ----------------------- |
| 微服务先行   | MVP 就拆 5 个服务        | 单体 + 模块化，接口留好 |
| 表结构拍脑袋 | 没有唯一键/索引          | 先写查询再倒推索引      |
| 契约后置     | 前端等后端定字段         | 先冻结 OpenAPI          |
| 忽略失败模式 | 外部 API 挂了就白屏      | 降级 + 缓存 + 兜底数据  |
| 过度抽象     | 为 1 个数据源写 5 层工厂 | 两个以上实现再抽        |
