# 部署服务器规格建议（2026-11-19 实测）

数据来自 Docker 栈实测（`docker stats` / `docker system df` / 库表大小），不是估算。

## 一、实测资源占用

| 组件                       | 常驻内存     | CPU（空闲） | 镜像               | 说明                   |
| -------------------------- | ------------ | ----------- | ------------------ | ---------------------- |
| poi-web（nginx + 静态）    | **16 MB**    | ~0%         | 78 MB              | 纯静态 + 反代          |
| poi-backend（Spring Boot） | **258 MB**   | ~0.1%       | 367 MB             | 含 JVM + Hikari 连接池 |
| poi-mysql（8.0）           | **470 MB**   | ~0.5%       | 1.1 GB             | 数据仅 17 MB           |
| **合计（空闲）**           | **≈ 750 MB** | <1%         | ≈ 450 MB（去重后） |                        |

- 数据库大小：**17 MB**（17 张表，银行 1,528 / 小区 3,605 / 待定位 4,941 / 字段来源 9.5k）
- 5,000 条全量接口响应：**1.4 MB**（lite 投影，未压缩）

## 二、推荐配置

### 最小可用（内网演示 / 答辩现场）

| 项   | 规格                     |
| ---- | ------------------------ |
| CPU  | **2 vCPU**               |
| 内存 | **4 GB**                 |
| 磁盘 | **40 GB SSD**            |
| 带宽 | 5 Mbps                   |
| 系统 | Ubuntu 22.04 / 24.04 LTS |

理由：三容器空闲占用 750 MB，但**镜像构建**（Maven 编译 + pnpm 构建）会瞬时吃掉 2 GB 以上；4 GB 是"能构建 + 能跑"的底线。

### 推荐（小范围试用，10–50 人）

| 项   | 规格          |
| ---- | ------------- |
| CPU  | **4 vCPU**    |
| 内存 | **8 GB**      |
| 磁盘 | **80 GB SSD** |
| 带宽 | 10 Mbps       |

理由：5,000 条全量接口单请求约 60–90 ms，并发 20 时 p95 约 0.2–0.6 s；4 vCPU 能把 JSON 序列化与 gzip 的 CPU 开销摊开。MySQL 与后端分到不同核，构建与运行不互相拖慢。

### 生产（真实用户）

不建议直接单机上线，先补：TLS 证书、独立 DB 账号与备份、可观测性（actuator/metrics 已具备）、资源限额与多副本。按上述推荐配置起步，**数据库单独一台 4C8G + SSD**，应用 2 台 × 4C8G 做滚动。

## 三、关键参数对照

| 参数          | 当前值                               | 建议                             |
| ------------- | ------------------------------------ | -------------------------------- |
| JVM 堆        | `MaxRAMPercentage=75%`（按容器内存） | 容器 2 GB 时堆约 1.5 GB，够用    |
| Hikari 连接池 | 10                                   | 单实例够用；多实例按 DB 上限调整 |
| MySQL 缓冲池  | 默认（128 MB）                       | 数据 17 MB，无需调               |
| 日志          | 容器 json-file 10 MB × 3             | 长期运行建议接外部日志系统       |

## 四、带宽估算

- 首屏地图一次拉全量 lite ≈ **1.4 MB**（gzip 后更小）
- 10 个用户同时打开 ≈ 14 MB 瞬时流量，10 Mbps 带宽约 11 秒摊平
- 静态资源（JS/CSS）约 620 KB，命中浏览器缓存后基本不再走网络

## 五、部署前置条件

1. 服务器能访问：`registry-1.docker.io` 或国内镜像源（镜像拉取）；Maven Central / npmmirror（构建时）
2. 开放端口：`8081`（HTTP，自动跳 HTTPS）、`8443`（HTTPS）、`18080`（仅本机，供排障）
3. `.env` 中必填：`MYSQL_ROOT_PASSWORD`、`DB_PASSWORD`、`AUTH_SECRET`、`OPERATOR_PASSWORD`
4. 首次启动会自动跑迁移（V1/V2/V3），无需手工建库
