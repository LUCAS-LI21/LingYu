# 坐标补全方案调研（2026-11-16）

> 目标：给 4 941 个待定位小区（有名称 + 完整地址）补经纬度，且**坐标必须可合法存储**。

## 一、已排除

| 方案                                  | 结论          | 依据                                                                                                                                              |
| ------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 高德/百度/腾讯 地理编码               | ❌ 不能存储   | 高德开放平台服务协议 3.5：「不得直接存储、缓存或技术手段抓取、使用本服务内部数据」；离线使用需购买技术服务许可并工单申请                          |
| 深圳市政府开放数据（建筑物/地名审批） | ❌ 无坐标字段 | 实测字段只有名称/地址/编码：[建筑物数据](../design/数据源矩阵.md) 52.5 万条仅 `NOWNAME/BLDADDR/BLDG_NO`；地名审批 2 856 条仅 `PZSJ/DMDZ/CYM/PZMC` |
| 网传「深圳 38 万栋建筑矢量数据」      | ❌ 来源不明   | CSDN 转载，无原始出处与许可证，不能用于合规项目                                                                                                   |

## 二、候选方案

### 方案 A：OSM 自建 Nominatim（推荐）

- **数据来源**：OpenStreetMap 中国区数据（[Geofabrik China extract](https://download.geofabrik.de/asia/china.html)，ODbL 许可）
- **做法**：Docker 起 Nominatim + 导入中国/深圳 PBF → 用 4 941 条地址做正向地理编码
- **合规**：ODbL 允许存储与再分发（需署名），结果可入库
- **优点**：完全自控、可批量、可重复；地址解析结果与我们的 WGS-84 坐标天然一致
- **风险**：
  - 深圳 OSM 门牌覆盖率参差：我们现有 3 601 个小区里 63% 有 `addr:*`，说明中心城区尚可、坪山/龙岗/盐田只有 4–8%（详见 MEMORY 第十九轮）
  - 需 ~30–50GB 磁盘、导入耗时数小时
- **预期命中**：中心城区可能 40–60%，外围较低；作为「能补多少补多少」的方案可接受

### 方案 B：Overture Maps（需先核实中国覆盖）

- **性质**：Linux 基金会下的开放地图数据集，多主题（places / addresses / buildings），CDLA-Permissive 2.0 等宽松许可
- **现状**：官方 [归属页面](https://docs.overturemaps.org/attribution/) 的 **addresses 主题只列出欧美 + 台港澳等地，没有中国大陆**；places 主题的中国覆盖未核实
- **判断**：即便有 POI，也大概率缺门牌级地址，不适合作为主方案；可作为补充验证

### 方案 C：建筑轮廓数据集（Microsoft / Google Open Buildings）

- 只有**建筑多边形**，没有名称与地址
- 可用于「校验」：如果某地址解析出的点落在建筑轮廓内，可信度更高
- 单独使用无法把「小区名」映射到坐标

### 方案 D：众包（已实现）

- 后台「待定位小区 → 标注位置」，用户/管理员在地图上点选
- 坐标是我们自己产生的，**零合规风险**
- 缺点：覆盖率取决于人力，适合作为兜底与运营闭环

## 三、建议路线

1. **先做方案 A 的可行性验证**（1–2 小时）：下载深圳范围的 OSM 数据 → 用 Nominatim 或轻量方案对 200 条地址做抽样地理编码，统计命中率
2. 命中率 ≥ 40% → 全量跑 4 941 条，结果写 `community_pending.lng/lat`（`geocode_source='osm'`），人工抽查后转正
3. 命中率 < 20% → 放弃全量，改为「重点小区优先 + 众包兜底」
4. 方案 B/C 作为交叉校验，不作为主数据源

## 四、待验证项
