## 一、P0（不解决就不能交付）

### 1. 小区「均价 / 建成年份 / 物业费」仍是哈希演示值

- **证据**：`SELECT COUNT(*) FROM poi_community WHERE demo_attributes=1` → **3605/3605**；
  新抓取的小区仍由 `IngestService.java:189-191` 用 `DemoData` 生成，占比只会更高不会更低。
  UI 已在卡片、筛选器、详情页、洞察页四处标注「演示属性」——这解决的是**诚实度**，不是赛题要求。
- **动作**：答辩口径统一为「字段级演示、不参与决策」；若仍想满足要求，政府参考价实测仅覆盖 5%（已试过 B 方案），
  只能走众包补录或接合规商业源。

### 2. 「待定位网点」闭环末端没有界面

- **证据**：`GET /api/v1/admin/pending` 返回 **50 条**（兴业银行官网导入）；用户「新增点位」审核后
  `pendingStaged=true` 会写进 `bank_pending`（实测 id=52/53），但：
  `src/` 全目录 grep `promote` / `admin/pending` **零命中**，后台 9 个 Tab 里没有这个页面；
  而审核 toast 明确写「点位已进待定位队列」——评委照着找会发现无处可看。
- **动作**：后台加「待定位网点」页（列表 + 地图点选坐标 + `POST /admin/pending/{id}/promote` 转正），
  与现有 `CommunityPendingPanel` 同构，半天工作量。

## 二、P1（演示会当场翻车）

### 3. 抓取成功率 2.5%，失败时长期占锁

- **证据**：`ingest_job` 366 条 → **9 成功 / 257 partial / 100 失败**；
  最近失败原因 `HttpTimeoutException: request timed out`（job 364 从 02:25 跑到 02:33，450 秒）；
  任务运行期间 `POST /api/v1/admin/jobs` 连续 6 次返回 409「已有抓取任务在执行」；
  服务重启会把在跑任务计为 failed（job 365/366 均为「服务重启导致任务中断」）。
- **动作**：演示前预热一次成功任务；把单次超时与镜像轮数压到 1 轮快速失败，避免 8 分钟占锁。

### 4. 独立部署从未实跑（赛题非功能 4 是硬性要求）

- **证据**：`docker info` → daemon 未运行；`docker-compose.yml` + 双 Dockerfile 静态自洽
  （`finalName=poi-intel`、nginx 无 rewrite、backend 有 HEALTHCHECK），但没有任何 `compose up` 记录。
- **动作**：启动 Docker Desktop，按 `docs/deploy/一键部署.md` 跑通并截图留证。

### 5. 公共接口错误码全归 500，小程序/第三方无法排错

- **证据**：`GET /api/v1/live/address`（缺参数）→ 500；`GET /api/v1/pois/nearby`（缺参数）→ 500；
  `POST /api/v1/admin/agent/suggest`（未映射路由）→ 500；`POST /api/v1/admin/feedback/NOPE/approve` → 500；
  `/api/v1/meta` 只列路径、不写必填参数，按文档调用即 500。
- **动作**：`GlobalExceptionHandler` 补 `MissingServletRequestParameter` / `MethodArgumentTypeMismatch` /
  `NoResourceFound` / `EmptyResultDataAccess` → 400 / 404 / 409。

## 三、P2（影响可信度与体验）

### 6. `/pois/nearby` 响应结构与契约不一致

- **证据**：实际返回 `{items:[{poi:{...},distance}]}`，其它列表接口都是扁平 `items[]`；
  `/meta` 与 `docs/miniprogram/后端契约.md` 都没写这个嵌套；smoke 脚本只断言 `items.length` 故没暴露。
- **动作**：契约补字段说明，或直接拍平为 `items[].id/name/distance`。

### 7. 默认只显示银行图层，搜索小区名提示「没有符合条件的点位」

- **证据**：Playwright `/list?keyword=水斗富豪新村` → 0 张卡片 + 「没有符合条件的点位」；
  点「小区」图层后出现 1 条。`DEFAULT_FILTERS.layers=['bank']` 是刻意选择，但搜索场景被它坑了。
- **动作**：有关键词时自动包含两类，或空结果时提示「当前仅显示银行图层」。

### 8. 「新增点位」表单没有「新点位名称」输入

- **证据**：正确值标为「选填」，后端 `PendingBankService.feedbackOf` 拿不到就退回问题说明；
  实测暂存表出现 `name="这里周边缺少一家营业网点，请补充采集"` 这种句子（已清理）。
- **动作**：`type=add` 时单独加必填「新点位名称」，前端校验 + 后端拒绝空名。

### 9. 数据版本只写不读

- **证据**：`poi_version` 4414 行，代码里只有 INSERT（AdminService / IngestService / ImportService / AgentService），
  无任何查询接口与界面，概览只显示一个计数。
- **动作**：加 `GET /api/v1/pois/{id}/versions`，详情页「变更历史」折叠块。

### 10. 众包坐标没有用户端入口，且可重复提交

- **证据**：公开 `POST /api/v1/community-pending/{id}/locate` 全链路可用（提交→审核→转正→bbox 可见），
  但前端只调 `/admin/community-pending/{id}/locate`（管理员直标）；
  同一小区连点两次产生 2 条 pending 记录，不去重。
- **动作**：用户后台/待定位页加「标位置」入口走公开接口；提交前按 `pending_id` 查重。

### 11. 跨源自动去重只在导入路径

- **证据**：165m 同名判定只在 `ImportService.java:38`；`dedupe_log`（222 条）只被读、从不自动写入；
  库内仍有 **38 对**同品牌且 ≤60m 的 OSM×官网重复网点（SQL 实测）。
- **动作**：把 165m 判定接进 OSM upsert，命中写 `dedupe_log`。

### 12. 零散不一致

- `index.html` 标题仍是模板「BISAI Agent」，description 是「全流程网站工程骨架」；
- 反馈表单文案「低风险字段会先以『用户提供』展示」与 `app.feedback.auto-apply=false` 矛盾；
- 地址缺失：银行 406/1523、小区 1301/3605（源头如此，UI 已标「地址待补充」，可接受但要有说法）。

## 结论

**距离「可交付」还差 5 件事**：① 待定位网点后台页（补上闭环最后一公里）；
② 小区价格类字段定性（接真源或答辩明确降级）；③ 一次稳定成功的抓取演示；
④ 独立部署实跑一次；⑤ 接口错误码与 `/meta` 契约规范化（配合小程序联调）。
