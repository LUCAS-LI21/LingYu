# ① 需求分析

> 目标：把「我想要一个能比赛的网站」拆成**可验收**的用户故事，并让所有人看同一份文档。

## 用到的工具

| 工具                 | 作用               | 为什么选它                                            |
| -------------------- | ------------------ | ----------------------------------------------------- |
| VitePress            | 需求文档站         | Vue 官方文档同款，Markdown 写、秒级热更新、可内网部署 |
| Markdown + 表格/清单 | 流程与状态枚举     | 纯文本可评审、可 diff                                 |
| 路由约定             | 页面清单即需求清单 | 需求和代码结构同步演进                                |

## 落地动作

1. 建 `docs/` 下的 PRD 页面，一个核心场景一个文件。
2. 用户故事统一格式：

   ```text
   作为 <角色>，我希望 <能力>，以便 <价值>。
   验收：给定 <条件>，当 <操作>，则 <可观测结果>。
   ```

3. 画出主流程与异常分支（登录失败、接口超时、空列表）。
4. 明确非功能需求：首屏 LCP < 2.5s、支持移动端、错误可观测。

## 验收清单

- [ ] 每个页面有明确入口与退出路径
- [ ] 每个用户故事至少一条可自动化验证的验收条件
- [ ] 非功能指标写进文档（后续由 web-vitals 度量）

## 常用命令

```bash
pnpm docs:dev      # 本地写文档
pnpm docs:build    # 产出静态文档站
```
