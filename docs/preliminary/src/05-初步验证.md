# 1 技术选择

系统采用 Vue 3 + TypeScript + Leaflet 的前端、Spring Boot 3 + MySQL 8 的后端、Docker Compose 的部署方式，AI 部分用 DeepSeek 做信息抽取。技术上真正有难度的不是框架本身，而是四件事：**多源异构数据的清洗与去重**、**坐标系混用（WGS-84 / GCJ-02 / BD-09）**、**公共数据源的不稳定**、**合规边界下的"能看不能存"**。因此验证重点放在这四条及其对应的用户可见结果上，而不是逐个框架做冒烟测试。

# 3 验证结果

## 3.1 接口连通性与契约一致性

按"每个接口至少一次真实调用、记录状态码与耗时"的方式取证，共 20 项，全部通过。节选如下（完整表格由脚本输出到 `docs/preliminary/assets/evidence-snapshot.md`）：

表 3 接口快照（节选，2026-11-22 13:48）

| 接口 | 方法 | 状态码 | 耗时 | 返回要点 |
| --- | --- | --- | --- | --- |
| `/api/v1/health` | GET | 200 | 31 ms | `{"status":"ok","db":"up"}` |
| `/api/v1/pois?size=3` | GET | 200 | 31 ms | `total=5428`，含 `gcjLng/gcjLat` |
| `/api/v1/pois/nearby?radius=1000` | GET | 200 | 10 ms | 50 条，按距离升序 |
| `/api/v1/stats` | GET | 200 | 26 ms | 银行 1,859 / 小区 3,569 |
| `/api/v1/pois/{id}/sources` | GET | 200 | 6 ms | 字段级来源逐条返回 |
| `/api/v1/admin/overview`（带 token） | GET | 200 | 17 ms | 待审反馈、任务、版本数 |
| `/api/v1/admin/overview`（无 token） | GET | 401 | 2 ms | 鉴权生效 |
| `/api/v1/not-exist` | GET | 404 | 4 ms | 未知路径不返回 500 |

在快照之外，另跑了一套 32 项的接口验收，覆盖正向、反向、幂等、鉴权与边界：

```text
PASS  健康检查返回 200 且 code=0  → status=200
PASS  stats.total 与列表 total 一致  → 5428 vs 5428
PASS  不存在的点位返回 404  → status=404
PASS  周边缺参返回 400  → status=400
PASS  无 token 访问后台返回 401/403  → status=401
PASS  错误口令返回 401/429  → status=401
PASS  重复驳回被拒绝（幂等保护）  → status=409
结果：通过 32 / 32
```

## 3.4 周边关联查询

以福田中心区（114.0579, 22.5431）为圆心查 1 公里内银行，返回 50 条（limit 上限），最近一条为：

```json
{"name": "招商银行深圳时代广场支行", "distance": 83.34,
 "address": "深圳市福田中心区益田路4068号卓越时代广场一楼", "source": "招商银行官网"}
```

用独立公式复核首条距离（WGS-84 球面距离）误差小于 0.5 米。反向关联（某银行服务半径内的小区）接口同样可用，详情页会列出小区名称、均价与距离。

## 3.5 闭环 A：纠错 → 审核 → 版本 → 主表

以真实反馈 `FB20261119-0103` 为例，三个时间点同秒完成，链路完整：

表 6 闭环 A 时间线与数据变化

| 环节 | 数据 | 说明 |
| --- | --- | --- |
| 用户提交 | `feedback`：`field=电话`、`new_value=0755-11112222`、`status=pending` | 接口返回受理编号 |
| 运营采纳 | `status=approved`、`reviewer=operator`、`reviewed_at=02:52:28` | 审核人取自 token，不信请求体 |
| 版本留痕 | `poi_version`：`change_type=update`、`changed_fields=phone=0755-11112222`、`feedback_id=103` | 可回放到任意一次变更 |
| 主表生效 | `poi_bank.phone = 0755-11112222` | 详情接口立即返回新值 |

核对命令与结果：

```sql
SELECT code,status,reviewer FROM feedback WHERE code='FB20261119-0103';
-- FB20261119-0103  approved  operator
SELECT changed_fields,feedback_id FROM poi_version WHERE feedback_id=103;
-- phone=0755-11112222  103
SELECT phone FROM poi_bank WHERE id='osm-node-13526829501';
-- 0755-11112222
```

## 3.6 闭环 B：审核新增点位 → 定向抓取任务

提交一条"新增点位"反馈并采纳，接口返回暂存与任务信息：

```json
{"code": 0, "data": {"code": "FB20261119-0099", "status": "need_refetch", "applied": [],
 "anchorLng": 114.052335, "anchorLat": 22.649201,
 "pendingStaged": true, "pendingKind": "bank", "jobId": 440}}
```

数据库对账：`ingest_job` 新增一条 `trigger_type=feedback`、`feedback_code=FB20261119-0099` 的任务，范围是锚点 ±0.012°（约 1.3 公里）；同时 `bank_pending` 新增一条待定位记录。该次抓取因公共 Overpass 实例超时未取到数据（任务记 `failed`），但"审核 → 建任务 → 暂存"这一跳已验证通过——抓取失败属于外部源问题，不影响闭环结构。验证后测试数据已清理。

## 3.7 闭环 C：查询 → 热点 → 调度

每次列表与周边查询写 `query_log`，聚合后得到 `hot_region`，调度器按优先级挑网格。当前 103 条热点记录，最高优先级 27，对应网格在 2026-11-21 有 25 次查询、1 次零结果；`ingest_job` 中 `trigger_type=hotspot` 的任务 463 条，说明调度确实在按热点跑。零结果权重为 2 倍，用于优先补"有查询但没数据"的区域。

## 3.8 AI 信息抽取样例

DeepSeek 只做"建议"，不直接写库。以 `agent_run#109` 为例：输入是某银行网点的名称与地址，模型在 1.8 秒内返回营业时间，并附带可回到原文的证据与来源 URL，置信度 0.9：

```json
{"value": "周一至周五对公09:00-12:00,14:00-17:00 对私09:00-17:00 周日对私09:00-15:00",
 "evidence": "营业时间 周一至周五对公09:00-12:00,14:00-17:00 对私09:00-17:00 周日对私09:00-15:00",
 "sourceUrl": "https://ditu.city8.com/sz/financial/862uh670bsjvbd3e1c",
 "confidence": 0.9, "problems": []}
```

累计 115 次运行，采纳后写入主表并记 `poi_version`（`operator=agent:operator@来源域名`）。建议必须带可复现证据、地址必须包含所属行政区，否则进人工复核队列。

## 3.9 独立部署与降级

Docker Compose 三个容器（MySQL / 后端 / Nginx 前端）在本机跑通：API `127.0.0.1:18080/api/v1/health` 返回 `{"status":"ok","db":"up"}`；Web `8081` 正常加载并读到实时数据。

后端停机时前端不会白屏：顶部出现"后端未连接，当前展示内置示例数据"横幅，地图回落到内置种子（339 条），核心浏览功能仍可演示。

# 4 其他

**结论**：关键路径已跑通并留有证据——接口 20/20 快照、32/32 验收；数据库 5,428 个点位自洽（银行 1,859 含 ATM 368 + 小区 3,569）；三条闭环各有一次真实链路记录；独立部署环境可访问；异常与降级行为符合设计。

**待办**：（1）后端 36 项单测中 33 项通过，`PoiServiceStatsTest` 3 项因当前沙箱禁止 Mockito 自附加进程无法运行，需在无沙箱环境复跑确认；（2）前端 75 项单测、20 项端到端用例（另 4 项跳过）需在最终构建上复跑并补截图；（3）抓取任务有效产出率 58.8%，演示前用镜像轮换再压一轮；（4）界面截图将随最终构建更新。
