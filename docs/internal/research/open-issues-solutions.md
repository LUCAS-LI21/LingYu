## 一、小区均价 / 建成年份 / 物业费是演示值（P0）

**现状**：`poi_community` 3 576 条全部 `demo_attributes=1`，三个字段由 `SeedRunner` 用哈希生成（`backend/src/main/java/com/poiintel/seed/SeedRunner.java`）。

**为什么是问题**：赛题第一条硬性要求「小区（……建成年代、均价、物业费……）」。评委一旦抽查就能看出是伪造值，且价格筛选、排序、洞察图表都建在这批数据上。

**方案（按代价从小到大）**

| 方案            | 做法                                                                                  | 代价   | 风险                                 |
| --------------- | ------------------------------------------------------------------------------------- | ------ | ------------------------------------ |
| A. 明确降级     | UI 把三字段统一标注「演示数据，不参与决策」，洞察页价格分布加醒目提示；答辩时主动说明 | 0.5 天 | 仍是假数据，只能算诚实，不算满足要求 |
| B. 政府参考价   | 用已有的「住宅小区二手住房成交参考价格表」（463 条，罗湖）匹配，匹配上的用真实价      | 1 天   | 覆盖率低（此前实测 1/463 名称重合）  |
| C. 众包补录     | 详情页允许用户提交均价/年代，审核后入库（复用现有反馈链路）                           | 2 天   | 需要用户量，短期只有个位数           |
| D. 接商业数据源 | 贝壳/安居客等（需核实条款，多数禁止抓取）                                             | 不确定 | 合规风险高，不建议                   |

**建议**：A 立即做（半天内把"演示"标识做实），B 作为补充尝试，C 作为长期机制写进闭环叙事。

**验收**：洞察页与详情页对演示字段有一致标识；若 B 成功，至少 N 个小区有权威参考价并标注来源。

## 二、抓取任务成功率低（P1）

**现状**：352 个 `ingest_job` 中仅 8 成功、92 失败、251 partial；Overpass 频繁 504，且当前 OSM 相关域名在本机网络下全部不可达（`overpass-api.de` / `geofabrik.de` / `osm.org` 均返回 000）。

**为什么是问题**：现场演示「手动触发抓取」可能直接失败；赛题要求「定时自动抓取」，任务大面积失败会削弱可信度。

**方案**

1. **缩小 bbox**：单次抓取范围从 0.06° 降到 0.01°（约 1km²），失败率显著下降，用「多次小块」替代「一次大块」。
2. **指数退避 + 重试**：504 时按 5s/15s/45s 重试 3 次，仍失败才记 failed，并把失败原因写进 `ingest_job.error`。
3. **多镜像**：Overpass 主站 + kumi + private.coffee 轮换（脚本已内置，抓取服务需同步支持）。
4. **自建 Overpass/Nominatim**：彻底摆脱公共实例限流（见 [坐标方案调研](coordinate-system-research.md)），代价是磁盘与导入时间。
5. **演示兜底**：后台「触发抓取」在失败时明确显示原因（已修 UI），并保留「上次成功时间」指标。

**工作量**：1–2 天（1+2+3），自建实例另算。

**验收**：连续 10 次小 bbox 抓取成功率 ≥ 80%；失败任务在后台能看到错误原因。

## 三、地图性能：5000+ 点位全量重建（P2）

**现状**：`MapCanvas` 在 `moveend/zoomend` 与每次筛选时全量重建 marker，无聚合与防抖。

**方案**

1. `moveend` 防抖 200–300ms，避免拖动过程中反复重建。
2. 按 zoom 做聚合：zoom < 14 用网格聚合（同一格只画一个带数字的圆），zoom ≥ 15 画单点。
3. marker 复用：维护 `Map<id, marker>`，只增删差量，不做整体 clear。
4. 首屏按 bbox 拉取（后端已支持 `west/east/south/north`），不要一次拉全量。

**工作量**：1–2 天；**验收**：拖动/缩放帧率稳定，福田视野（千级点位）不卡顿。

## 四、登录限流与默认口令（P2）

**现状**：`operator/operator123` 是默认账号，登录接口无限流。

**方案**

1. 部署时强制 `OPERATOR_PASSWORD` 环境变量；未设置且非 dev profile 时**拒绝启动**。
2. 登录失败按 IP 限流：5 次/分钟，超限返回 429。
3. token 有效期可配（当前 7 天），后台「退出」应使 token 失效（可加黑名单表）。
4. 审计：登录成功/失败写 `query_log` 之外的独立表，便于排查。

**工作量**：0.5–1 天；**验收**：默认口令无法启动；暴力尝试被限流。

## 五、Docker 部署未实测（P1）

**现状**：`docker compose config` 通过，但 Docker Desktop 未运行（`docker info` 报 daemon 不存在）；nginx 反代路径 bug 本轮已修但未实跑。

**方案（按顺序）**

1. 启动 Docker Desktop（或装 Linux 版 Docker Engine）。
2. `docker compose --env-file .env.deploy.example up -d --build`
3. 验证清单：
   - `curl http://localhost:8081/api/v1/health` → 200
   - 前端 `http://localhost:8080` 能打开并显示数据（不是本地种子）
   - 后台登录 → 审核 → 地图可见（验证闭环）
   - `docker compose logs backend` 无异常
4. 在 CI 里加 `docker build` 冒烟（GitHub Actions 自带 Docker）。

**工作量**：0.5 天（含排错）；**验收**：一台干净机器按文档 10 分钟内跑起来。

## 六、测试覆盖缺口（P2）

**现状**：前端 76 例覆盖 api/详情/管理/Agent/导航/追踪；**未覆盖** `MapCanvas`（框选、聚合）、`ListView`（筛选分页）、`CommunityPendingPanel`（坐标提交）、`CoordinatePicker`；e2e 不含管理后台。后端 30 例，无 Controller 层测试。

**方案**

1. 前端补 4 个组件测试（mock Leaflet，验证 emit 与状态）。
2. 加 2 条 e2e：管理后台审核流程、待定位小区标注流程（Playwright 已具备）。
3. 后端用 `@SpringBootTest` + H2 或 Testcontainers 补 Controller 冒烟（`/pois`、`/feedback`、`/admin/feedback/approve`）。
4. 清理 `src/lib/http.ts`（0 引用死代码）与其测试。

**工作量**：1–2 天；**验收**：核心链路有回归保护，`pnpm check` + `mvn test` 全绿。

## 七、Overpass 使用频率与合规说明（P2）

**现状**：调度器每 30 分钟请求一次 Overpass 公共实例，未在文档中说明频率与退避策略。

**方案**：在 [合规与数据来源](../requirements/03-compliance-and-data-sources.md) 增加一节：

- 抓取频率：30 分钟/次，单次 bbox ≤ 0.06°
- 失败退避：504 时 5s→15s→45s，三次仍失败则跳过本轮
- 尊重公共实例：不在高峰时段批量抓取，必要时改用自建实例
- 数据许可：OSM 数据为 ODbL，界面署名「© OpenStreetMap contributors」

**工作量**：0.5 小时（文档）；**验收**：合规文档有明确条目，可对评委复述。

## 八、审核不改字段来源（P2）

**现状**：用户反馈审核通过后写 `poi_version`，但没有更新 `poi_field_source`，字段来源仍显示原来源（如「银行官网」）。

**方案**：`AdminService.approve` 写入字段后，同步 `INSERT ... ON DUPLICATE KEY UPDATE` 到 `poi_field_source`，来源记为 `用户反馈（审核:xxx）`。

**工作量**：0.5 天；**验收**：审核后详情页「数据来源」显示该字段来自用户反馈。

### B 方案实测结论（2026-11-16）

政府「住宅小区二手住房成交参考价格表」420 条（仅罗湖），用名称归一化匹配本地小区，
只对上 **23 个（5%）**——命名体系差异太大（「XX大厦」vs「XX小区」）。

**结论：放弃 B，价格字段保持演示值 + 全站显式标识**（列表卡片带「演示属性」、筛选器标「演示」、
详情页提示、洞察页徽章）。
