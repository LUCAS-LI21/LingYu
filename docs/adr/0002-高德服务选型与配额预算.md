# ADR-0002：高德开放平台服务选型与配额预算

- 状态：**提议（待确认）**
- 日期：2026-11-07
- 决策者：项目负责人 + 开发
- 相关需求：FR-D-17、FR-D-18、FR-Q-07、§7.5 风险表、Q3/Q4
- 关联：[ADR-0001 实时层与本地库分离](0001-实时层与本地库分离.md)

## 1. 问题

赛题要求"从地图服务获取数据"，团队担心"调用高德 API 很贵"。真正要回答的是四个问题：

1. 开通**哪个平台类型**的 Key（Web 服务 / JS API / Android / iOS / 小程序）？
2. 开通**哪些接口**？
3. 每月**最多花多少钱**？
4. 哪些服务**看起来有用、实际不该开**？

前提不变：高德服务协议 3.5 条禁止存储/缓存 API 返回数据，高德只能做 L2「即取即显」（ADR-0001）。

## 2. 已核验的计费事实（2026-11-07，官方页面）

来源：<https://lbs.amap.com/pages/base_service_price>、<https://lbs.amap.com/upgrade#price>（两页互相印证）。

月配额（次/月）与 QPS：

| 服务类别 | 包含接口 | 未认证 | **个人认证** | 企业认证（乘风） | 企业（技术服务许可） |
| -------- | -------- | ------ | ------------ | ---------------- | -------------------- |
| 基础 LBS | 逆地理编码、地理编码、静态地图、路径规划、距离测量、IP 定位、行政区划 | 0 | **150,000**（3 QPS） | 3,000,000（30 QPS） | 9,000,000（100 QPS） |
| 基础地图定位 | JS 地图图面初始化、在线定位 | 0 | **1,500,000**（10 QPS） | 30,000,000（100 QPS） | 90,000,000（300 QPS） |
| 基础搜索 | **周边搜索**、关键字搜索、多边形搜索、ID 查询、输入提示 | 0 | **5,000**（3 QPS） | 50,000（30 QPS） | 500,000（100 QPS） |
| 天气 / 智能硬件定位 | — | 0 | 5,000 / 0 | 5,000 / 5,000 | 9,000,000 / 9,000,000 |

超量单价（2025-05-20 起执行的新定价）：

| 类别 | 0–30 万次/月 | 30–100 万 | >100 万 |
| ---- | ------------ | --------- | ------- |
| 基础 LBS | 30 元/万次（0.003 元/次） | 24 元/万次 | 18 元/万次 |
| **基础搜索** | 30 元/万次（**无折扣**） | 30 元/万次 | 30 元/万次 |
| 基础地图定位 | 3 元/万次 | 2.4 元/万次 | 1.8 元/万次 |

三条容易被忽略的规则：

1. **未认证 = 0 配额**：不实名认证不是"贵"，是直接调不通。
2. **免费月配额只有 1 年**："自注册认证之日起计算"，到期后按上表计费。
3. **配额跨平台共享**：同一账号下 API / JS / Android / iOS / 微信小程序的同类服务共用一个月配额池（官方表述"配额共享平台"）。前端 JS 的周边搜索与后端 around 接口吃的是同一个 5,000。

## 3. 决策

### 3.1 只开 1 个平台类型的 Key：Web 服务

| 项 | 决定 | 理由 |
| -- | ---- | ---- |
| Key 平台 | **Web 服务**（服务端调用，可选 IP 白名单） | LiveService 是后端中转，Key 不进前端 |
| JS API Key | **不开** | 底图维持 Leaflet + OSM 瓦片，开通即产生"图面初始化"计费项且要重写地图层 |
| Android / iOS / 微信小程序 Key | **不开** | 本项目是 Web，Key 类型错配会直接报 `INVALID_USER_KEY` |
| MCP Server | **不开** | 面向大模型工具调用，配额与 Web 服务同池，返回结构与本项目 LiveService 不兼容 |

### 3.2 只用 2 个接口，且都必须"用户点击"才触发

| 接口 | 用途 | 配额池 | 触发条件（必须同时满足） |
| ---- | ---- | ------ | ------------------------ |
| `GET /v3/geocode/regeo` | 详情页「查实时地址」 | 基础 LBS 15 万/月 | 用户点击 **且** 本地 `address` 为空 |
| `GET /v3/place/around` | 详情页「查 1km 内」兜底 | **基础搜索 5,000/月** | 用户点击 **且** 本地周边结果为 0 |

### 3.3 明确不接（省下的不是钱，是"看起来能用"的复杂度）

| 服务 | 不接的理由 |
| ---- | ---------- |
| 路径规划 / 距离测量 | 本地 `ST_Distance_Sphere` 已够用，且高德只收 GCJ-02，还要多做一次坐标转换 |
| 地理编码（地址→坐标） | 当前没有"地址转坐标"的需求；银行官网补地址是 L1 入库链路，不走 L2 |
| 行政区划 / 边界 | 深圳 10 区已在本地建模（`Districts.java`） |
| 静态地图 | 没有缩略图/分享图需求 |
| 天气、交通态势、猎鹰、物流、智能调度 | 与业务无关 |
| **输入提示（AutoComplete）** | 最贵的一类：与周边搜索共用 5,000/月，按击键触发一天就能打爆。搜索框继续走本地 MySQL |
| 批量补地址（4,000+ 条一次跑完） | 成本约 1.2 元（额度内），但**违反 3.5 条**——这是本案真正的红线，不是钱的问题 |

### 3.4 零配额替代：URI API 做"跳转"

`https://uri.amap.com/marker?position={lng},{lat}&name={name}&coordinate=wgs84&src=poi-intel`

- 官方文档：<https://lbs.amap.com/api/uri-api/guide/mobile-web/point>（2025-02-17 更新）
- 不消耗任何配额、不需要 Key，且 `coordinate=wgs84` 可直接传 OSM 原始坐标，**免坐标转换**
- 用途：详情页「在高德地图打开 / 导航」，比在页面内做路径规划便宜且合规

## 4. 成本模型

`月账单 = max(0, 月调用量 − 免费配额) × 单价`

| 场景 | 逆地理（15 万免费） | 周边（5,000 免费） | 月账单 |
| ---- | ------------------- | ------------------ | ------ |
| 演示 / 答辩（每天 100 次详情 + 50 次周边，22 天） | 2,200 | 1,100 | **0 元** |
| 压力测试（每天 1,000 次周边） | — | 30,000 | **75 元** |
| 最坏情况（地图 moveend / 输入框击键就调） | — | 150,000 | **435 元**，且 3 QPS 先被限死 |

**结论**：单价 0.003 元/次并不贵，演示期账单是 0；会变贵的是"调用粒度"——把"用户点击"改成"地图一动就查"，账单放大 100 倍，还先把 5,000/月的搜索配额打爆。

## 5. 方案对比

| 方案 | 月成本 | 合规 | 工作量 | 结论 |
| ---- | ------ | ---- | ------ | ---- |
| **Leaflet + OSM 底图 + 2 个 Web 服务接口**（本 ADR） | 0 | ✅ | 已实现 | **采用** |
| 高德 JS API 底图 + JS 搜索插件 | 0（1.5M 免费）～435 | ✅ | 重写地图层 2–3 人日 | 二期可选，先不动 |
| 高德 API 批量补 4,000 条地址入库 | ≈1.2 元 | ❌ 违反 3.5 | 小 | **否决**：便宜但违规 |
| 百度 / 腾讯作交叉源 | 0（各家免费额度） | ⚠️ 条款未核实 | 中 | 暂缓（见《数据源矩阵》§8） |
| 天地图底图 | 0 | ⚠️ 条款未核实 | 小 | 可选，解决 OSM 国内慢 |

## 6. 必须同步修的两个缺陷

1. **坐标系错配（P0）**：本地库是 WGS-84（OSM），而高德 `regeo` / `around` 只接受 GCJ-02，直接传会系统性偏移约 300–500 m（深圳），"实时地址"可能返回隔壁小区。修法：后端加本地 WGS-84→GCJ-02 换算（纯算法，**0 配额**），调用前转换；URI API 用 `coordinate=wgs84` 免转换。
2. **搜索配额误用（P1）**：`/v3/place/around` 个人只有 5,000/月，必须保持"按钮触发 + 本地优先"，禁止出现在 `watch` / `onMounted` / `moveend` 里。

## 7. 成本护栏（落地清单）

- [ ] 后端 `app.live.daily-budget`（默认 50 次/日）+ 当日计数器，超预算直接返回"今日实时额度已用完"，**不发请求**
- [ ] 前端按 `poi.id` 做会话内去重，同一 POI 不重复查
- [ ] 调用失败**不重试**（避免重试放大配额），超时 6 s，保持 `Cache-Control: no-store`
- [ ] 详情页「查 1km 内」按钮旁标注"每日额度有限"，避免演示时连点
- [ ] 监控：控制台「用量详情」+ 本地每日调用计数（只记次数，不记响应体）

## 8. 后果

**正面**

- 演示期账单 ¥0，答辩时能直接报出配额与单价，比"我们没敢用"更有说服力。
- 不需要改架构：现有 `LiveService` 已经是后端中转 + 无 Key 降级。
- 留了升级路径：若 Q3 改高德底图，只需加一个 JS API Key，配额 150 万/月，仍然免费。

**负面 / 代价**

- 底图仍是 OSM，国内首屏偏慢（已有灰度滤镜与本地种子兜底）。
- 周边搜索能力弱：个人 5,000/月，超了要 30 元/万次，且无折扣。
- 免费额度只有 1 年，一年后若仍在跑，按演示量级约 0–75 元/月。

**未验证项**

- 服务端中转高德结果再返回自建前端，3.5 条是否认可（ADR-0001 已列，建议工单确认）。
- URI API 是否长期免配额：官方文档未列计费项、不需要 Key，按"H5 跳转"理解风险低，但**未找到明文承诺**。

## 9. 一句话

**一个「Web 服务」Key、一个逆地理编码接口就够；周边搜索保留但按钮化；底图不换；导航用 URI API。演示期账单 0 元，贵的是"每次都调"的设计，不是单价。**
