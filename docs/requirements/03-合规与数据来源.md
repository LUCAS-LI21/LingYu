# 数据采集合规说明（硬约束）

> 赛题原文：「数据抓取不能违法」。本文档把合规要求变成**可执行的检查项**，每一步采集都要过这张表。

## 1. 数据来源分级

| 级别  | 来源类型                                 | 举例                                        | 允许    | 前置条件                           |
| ----- | ---------------------------------------- | ------------------------------------------- | ------- | ---------------------------------- |
| **A** | 官方开放平台 API                         | 高德开放平台 Web 服务 API、百度地图开放平台 | ✅ 推荐 | 申请 Key、遵守配额与 ToS、标注来源 |
| **B** | 明确许可的开放数据                       | 政府开放数据平台、国家统计局行政区划        | ✅ 允许 | 保留许可声明                       |
| **C** | robots 允许的公开页面                    | 银行官网"网点查询"页（robots 未禁止）       | ⚠️ 谨慎 | 检查 robots、限速、仅公开字段      |
| **D** | 需登录 / 有验证码 / 付费墙 / robots 禁止 | 房产网站详情页、需要会员的数据              | ❌ 禁止 | 一律不做                           |

**本项目的默认策略**：优先 A，必要时 B，C 只做人工确认过的少量补充，D 完全不碰。

## 2. 每次采集前的合规检查清单

- [ ] 目标域名在 `ds_source` 白名单内，且 `enabled=true`
- [ ] 官方 API：Key 有效、配额未超、请求参数符合文档
- [ ] 网页：`/robots.txt` 已抓取并缓存（≤24h），目标路径 `Disallow` 为空
- [ ] 请求频率 ≤ 配置值（默认 1 QPS），并发 ≤ 1
- [ ] User-Agent 标明项目与联系方式（如 `BISAI-POI-Bot/1.0 (+contact@example.com)`）
- [ ] 不携带、不存储任何个人身份信息
- [ ] 响应内容仅取业务字段，原始包按保留期存储且不对外分发

## 3. 技术实现要求（落到代码）

| 要求        | 实现方式                                                                   |
| ----------- | -------------------------------------------------------------------------- |
| 速率限制    | 令牌桶，每数据源独立；`rate_limit_qps` 可配；默认 1 QPS                    |
| 退避重试    | 指数退避 + 抖动；429/5xx 重试上限 3 次                                     |
| robots 校验 | `RobotsGuard` 组件，抓取前检查并缓存结果；不允许则抛 `ComplianceException` |
| 白名单      | 域名 + 路径前缀白名单，硬编码在配置中，运行时不可被接口篡改                |
| 紧急开关    | `poi.crawler.enabled=false` 一键停采（Kill Switch）                        |
| 审计        | 每次请求写 `ingest_log`（URL 脱敏、状态码、耗时、是否命中缓存）            |
| 密钥管理    | Key 存环境变量/加密字段，绝不写日志、不进 Git                              |

## 4. 法律边界（要知道自己在遵守什么）

- 《网络安全法》：不得从事非法侵入、干扰他人网络正常功能的活动。
- 《数据安全法》：数据分类分级，不得违规获取、交易数据。
- 《个人信息保护法》：**不采集个人信息**。商家公开电话属经营信息，但个人手机号一律不采集、不存储。
- 《反不正当竞争法》：不得以技术手段实质性替代他人服务、不得破坏他人技术措施。
- **robots 协议**：虽非法定强制，但违反会被认定为"未经许可的访问"，是合规判断的重要依据。

## 5. 免责声明页面要素（前端必须有独立页面）

1. 数据来源列表（含官方平台名称与许可类型）。
2. 更新频率说明与"数据仅供参考，以官方为准"。
3. 不采集个人信息的声明。
4. 联系与纠错入口（与反馈系统打通）。
5. 最后更新时间。

## 6. 演示时怎么讲合规（1 分钟话术）

> "我们只使用高德开放平台的官方 API 和明确允许的公开数据；每次采集都经过白名单校验和 robots 检查，速率限制在 1 QPS，全部请求有审计日志。系统内有紧急停采开关。页面上有独立的数据来源与免责声明页。"

## 7. 风险与红线

| 行为                     | 判定     | 处理                         |
| ------------------------ | -------- | ---------------------------- |
| 高频轮询导致对方服务压力 | 违规     | 限流 + 退避 + 缓存           |
| 绕过验证码/登录          | 违法风险 | 绝对禁止，代码层面不提供能力 |
| 抓取并展示个人手机号     | 违规     | 字段级过滤，手机号正则拦截   |
| 把原始数据打包分发       | 违反 ToS | 不提供导出原始包功能         |
| 未标注来源               | 违反 ToS | 详情页固定展示来源           |
