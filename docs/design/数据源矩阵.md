# 数据源矩阵：每个字段从哪来、能不能入库

> 回答两个问题：① 赛题要的字段分别由哪个源提供？② 哪些能存进本地库、哪些只能实时展示？
> 核验日期：2026-11-05。标注「未核实」的，请在启用前自行阅读该平台最新条款。

## 0. 一句话结论

**不能只靠 OSM**：它只能覆盖赛题 10 个字段中的 4 个（名称、坐标、部分地址、部分电话/营业时间），
且银行地址覆盖率仅 5.5%。正确做法是**多源分层**：能存的存（L1），只能看的实时取（L2），禁止的不碰（L3）。

## 2. 逐源分析

### 2.1 OpenStreetMap / Overpass —— L1 可入库 ✅

| 项     | 内容                                                                 |
| ------ | -------------------------------------------------------------------- |
| 许可   | ODbL 1.0，允许存储与再分发，需署名 + 同许可                          |
| 能提供 | 银行/ATM 节点、住宅面、名称、部分 `addr:*`、`phone`、`opening_hours` |
| 缺口   | 中国区属性稀疏；无均价/建成年代/物业费                               |
| 用法   | **主数据底座**：坐标与实体骨架                                       |
| 实测   | 深圳福田+罗湖 78 km² 内有 182 个银行/ATM 节点、792 个住宅面          |

| ------ | -------------------------------------------------------------------------------------------- |

| 用法   | **实时补全**：详情页「查实时地址」「查实时周边」，即取即弃，`Cache-Control: no-store`        |
| 限制   | 需 Key（个人开发者有免费额度，数值以控制台为准，**未核实**）；服务端中转是否合规建议工单确认 |

## 3. 为什么多源之后项目才有优势

| 维度       | 单源（只有 OSM）         | 多源分层                                                       |
| ---------- | ------------------------ | -------------------------------------------------------------- |
| 字段覆盖   | 10 个字段里只能覆盖 4 个 | 坐标/名称走 OSM，地址/电话/营业时间走银行官网，均价走政府+反馈 |
| 数据可信度 | 无法交叉校验             | 同一实体多源比对，一致则高置信，冲突则标"待核实"               |
| 抗故障     | Overpass 一挂就停更      | 单源失败只降级该源，其余照常                                   |
| 实时性     | 受限于 OSM 编辑频率      | 用户点开即查高德/百度，体验新                                  |
| 扩展性     | 加源要改核心代码         | 适配器模式：新增源只实现接口                                   |

**一句话**：赛题考的不是"你能抓多少"，而是"**你能把多少源的数据合规地组织成一个持续更新的系统**"。

## 4. 多源合并策略（已定，待实现）

```text
同一实体判定：source_ref 相同 → 合并
             名称相似(≥0.85) 且 坐标距离 < 100m → 合并
字段取值：按来源优先级 + 更新时间
             人工审核 > 银行官网 > 政府数据 > OSM > 用户反馈(待核实)
冲突处理：保留多值，展示用最高优先级，其余进"待核实"队列
每次合并写 poi_version，记录 before/after 与来源
```

## 6. 落地顺序（拿到 Key 后）

1. **P0**：高德 Key → 详情页「查实时地址 / 查实时周边」可用（代码已就绪，缺 Key）
2. **P1**：银行官网适配器 → 补地址/营业时间/电话进 L1 库（这是对数据质量提升最大的一步）
3. **P1**：百度 AK → 与高德交叉校验，冲突标待核实
4. **P2**：政府开放数据 → 行政区划 + 人口 + 小区名录
5. **P2**：天地图底图 → 替换 OSM 瓦片
6. **长期**：房产均价只能靠「政府参考价 + 用户反馈」，不碰 robots 禁止站点

## 7. 合规红线（再次确认）

- L2 数据**绝不写库**，响应头 `no-store`，日志不记响应体
- L3 站点（链家/贝壳）不访问，白名单直接拒绝
- 每源限速 ≤ 1 QPS，带自定义 UA 与联系方式
- 抓取前校验 `robots.txt` 并缓存结果
- 页面标注来源与许可，提供免责声明
