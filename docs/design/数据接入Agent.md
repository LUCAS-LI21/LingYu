# 数据接入 Agent（设计草案）

> 目标：把"每来一个新数据源就要人写一个适配器"变成"Agent 按工作流自动完成接入与补全"。
> 状态：**设计草案，待评审**。实现见后续提交。

## 1. 为什么需要

现状：65 个银行品牌 + 政府数据集 + 用户反馈，每家页面结构不同（建行是 `WCCMainPlatV5` 网关、
招行是 SPA、工行 JS 渲染）。人工一家家写适配器，TOP 10 就要 1–2 周。

## 2. 两条"AI 适配"路线（重要区别）

| 路线              | 做法                                                  | 风险                                     | 结论            |
| ----------------- | ----------------------------------------------------- | ---------------------------------------- | --------------- |
| A. LLM 写抓取代码 | Agent 生成 Python/JS 脚本并执行                       | 代码执行不可控、页面对不上就崩、难审计   | ❌ 运行时禁用   |
| B. LLM 做字段抽取 | 抓取仍由固定代码完成，LLM 只把页面内容转成结构化 JSON | 输出需 Schema 校验，幻觉可用证据片段拦截 | ✅ **默认路线** |

**A 的变体（推荐作为第二阶段）**：Agent 生成"适配器配置"（URL 模板、选择器、字段映射），
**人工审核后落库为配置**，运行时不执行任何 LLM 生成的代码。既省人力又不失控。

## 3. 运行时工作流（MVP）

```text
触发（反馈/手动/定时）
   │
   ├─1 意图解析：要补哪个实体的哪些字段（JSON Schema 约束）
   │
   ├─2 选源：按白名单 + 字段优先级选（政府/官网 > OSM > 用户反馈）
   │
   ├─3 抓取：robots 预检 → 限速 1 req/s → 存原始 HTML/JSON 快照（可溯源）
   │
   ├─4 抽取：LLM 输出 {field, value, evidence, confidence}，必须过 Schema
   │
   ├─5 校验：坐标范围 / 地址格式 / 与已有实体一致性 / 交叉源比对
   │
   ├─6 落库 or 人审：置信度 ≥0.85 自动写入；0.6–0.85 进审核队列；<0.6 丢弃
   │
   └─7 记账：agent_run（输入、步骤、token 消耗、结果、耗时）
```

## 4. 关键护栏

| 护栏     | 规则                                                        |
| -------- | ----------------------------------------------------------- |
| 源白名单 | 只允许已核验 robots 的域名；未核验域名直接拒绝              |
| 预算     | 单次 run ≤ 5 个请求、≤ 60 秒、≤ 8000 token；超限中止        |
| 证据     | 每个字段必须带 `evidence`（原文片段 + 来源 URL + 抓取时间） |
| 幂等     | 同一 (entity, field, source) 24 小时内不重复跑              |
| 幻觉拦截 | 值必须能在 evidence 中找到子串；地址必须匹配行政区词典      |
| 人审兜底 | 低置信度、与既有值冲突、涉及坐标/名称的变更 → 审核队列      |

## 5. 合规边界（用户想法的关键澄清）

用户设想：「官方文档找不到，就先上高德找名字，再按名字全网找数据」。

**这里有个坑**：高德返回的**名字本身也是"服务数据"**，直接写进我们库里仍然属于"存储"，
违反服务协议 3.5 条——不管后续有没有再搜一遍。

可行做法（**线索中转，不留痕**）：

1. 高德只在"人工/实时查询"时用来**发现**实体存在（不落库）
2. 拿到名称后，去**独立来源**（银行官网 / 政府数据 / OSM / 企业公示）确认并取数
3. 入库时 `source` 记录的是**独立来源**，不是高德
4. 若独立来源查不到，则该字段保持空缺——**宁可缺，不留违规来源**

> 一句话：高德可以作为"搜索框"，不能作为"数据源"。

## 6. 与赛题对应

- 「数据抓取与更新」：多源、可扩展
- 「业务闭环」：反馈 → Agent 补全 → 审核 → 生效
- 「便于扩展新的数据源」：Agent 配置化接入
- 答辩价值：把"人工写适配器"变成"Agent 按工作流接入"，是明确的创新点
