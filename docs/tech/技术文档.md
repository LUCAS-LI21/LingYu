## 二、具体功能

### 2.1 页面

| 路由          | 页面     | 核心能力                                                              |
| ------------- | -------- | --------------------------------------------------------------------- |
| `/`           | 地图查询 | 视口内渲染标记、图层切换、矩形框选、点击弹窗、详情侧栏、周边 1km 银行 |
| `/list`       | 列表查询 | 区域/类型/价格/年份筛选、排序、分页、详情抽屉、纠错入口               |
| `/stats`      | 数据洞察 | 数量卡片、品牌 Top8、均价分布、2km 网格密度                           |
| `/compliance` | 数据说明 | 三级授权模型、来源清单、不采集清单、免责声明                          |
| `/admin`      | 运营后台 | 概览、反馈审核、抓取任务、热点（需登录）                              |

### 2.3 三条数据闭环

| 链路       | 触发                  | 处理                                                                                   | 可见结果                                                                        |
| ---------- | --------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **A 纠错** | 用户提交反馈          | 低风险（电话/营业时间/均价/物业费/年份）→ 系统自动采纳；关闭/名称/坐标/新增 → 人工审核 | 主表更新 + 写 `poi_version` → 详情接口立即返回新值；关闭后从视图消失（总数 -1） |
| **B 补采** | 审核「新增点位」      | 取锚点坐标建定向任务（±0.012°，约 1.3km），`trigger_type=feedback`                     | 抓取完成后新点位入库，地图可见                                                  |
| **C 热点** | 每次 list/nearby 查询 | 写 `query_log` → 每日 02:30 或手动重算 → `hot_region` 按 `查询数 + 2×零结果数` 排名    | 定时任务自动挑选最高优先级网格抓取（`trigger_type=hotspot`）                    |

### 2.4 运营后台

| Tab      | 能力                                              |
| -------- | ------------------------------------------------- |
| 概览     | 待审反馈、任务数（成功/失败）、版本数、平均新鲜度 |
| 反馈审核 | 按状态筛选、采纳生效、驳回；采纳人取自 token      |
| 抓取任务 | 任务列表（状态/抓取/新增/更新/错误）、一键触发    |
| 热点     | 排名（优先级/查询数/零结果数）、一键重算          |

## 三、账号体系

### 3.1 角色

| 角色             | 说明                    | 能力                                             |
| ---------------- | ----------------------- | ------------------------------------------------ |
| 匿名访客         | 未登录                  | 浏览地图/列表/洞察/数据说明；提交反馈            |
| 运营（operator） | 内置账号，`sys_user` 表 | 登录后访问 `/admin/**`：审核、触发抓取、重算热点 |

MVP 只有两档角色，`sys_user.role` 字段保留扩展位。

### 3.2 口令存储

- 算法：**PBKDF2WithHmacSHA256**，迭代 120 000 次，输出 256 bit
- 存储：`base64(salt) $ base64(hash)`，16 字节随机盐
- 校验：`MessageDigest.isEqual` 常量时间比较，避免时序侧信道

### 3.3 会话

- 登录成功签发 **HMAC-SHA256** token：`base64url(payload).base64url(sig)`，payload 为 `username|expiresAt`
- 默认有效期 **720 分钟**（`app.auth.ttl-minutes`）
- 前端存 `sessionStorage`，每次请求带 `Authorization: Bearer <token>`
- 服务端由 `AdminAuthInterceptor` 拦截 `/api/v1/admin/**`，401 时前端自动清 token 回到登录页

### 3.4 密钥与账号配置

| 配置         | 环境变量               | 默认          | 说明                                                                    |
| ------------ | ---------------------- | ------------- | ----------------------------------------------------------------------- |
| 签名密钥     | `AUTH_SECRET`          | 空            | **留空则启动时生成随机密钥**并告警，重启后 token 失效；生产必须显式配置 |
| 运营账号     | `OPERATOR_USERNAME`    | `operator`    | 首次启动写入 `sys_user`                                                 |
| 运营口令     | `OPERATOR_PASSWORD`    | `operator123` | 使用默认值会打 WARN 日志                                                |
| Token 有效期 | `app.auth.ttl-minutes` | 720           | 分钟                                                                    |

> 修改口令：更新环境变量后删除 `sys_user` 中对应行，重启即重新播种。
> 演示环境默认账号：`operator / operator123`。

### 3.5 已知限制

- token 无 `jti`、无撤销列表：禁用账号需等 TTL 过期
- 无「首次登录强制改密」
- 无细粒度权限（运营 = 全权限）

## 四、使用说明

### 4.1 环境要求

| 依赖    | 版本    | 检查命令                |
| ------- | ------- | ----------------------- |
| Node.js | ≥ 20.19 | `node -v`               |
| pnpm    | ≥ 11    | `pnpm -v`               |
| JDK     | 17      | `java -version`         |
| Maven   | ≥ 3.9   | `mvn -v`                |
| MySQL   | 8.0     | 服务名 `MySQL80` 运行中 |

### 4.2 初始化数据库

```sql
CREATE DATABASE IF NOT EXISTS poi_intel
  DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

表结构由后端启动时执行 `backend/src/main/resources/db/schema.sql` 自动创建（幂等）；
首次启动会从 `classpath:seed/pois.json` 导入种子数据。

### 4.3 启动后端

```bash
cd backend
mvn -DskipTests package
java -jar target/poi-intel.jar
# → http://127.0.0.1:8080/api/v1/health
```

可用环境变量覆盖：`DB_USER`、`DB_PASSWORD`、`AUTH_SECRET`、`OPERATOR_PASSWORD`、`HTTP_PROXY`、`AMAP_KEY`。

`AMAP_KEY` 只用于详情页的「查实时地址」（L2）：调用高德逆地理编码后**直接返回给浏览器，不写库、不缓存**（响应头 `no-store`）。留空时该入口提示不可用，其余功能不受影响。

### 4.4 启动前端

```bash
pnpm install
pnpm dev            # http://127.0.0.1:5173
```

`vite.config.ts` 已配置 `/api` 代理到 `127.0.0.1:8080`，无需处理跨域。

### 4.5 演示脚本（5 分钟）

1. 打开 http://127.0.0.1:5173/ ，地图显示福田区银行点位，右侧列出结果
2. 点击一个小区 → 详情侧栏 → 「查周边银行」→ 展示 1km 内网点与距离
3. 点「提交纠错」，填写字段与说明 → 提交 → 拿到 `FB2026xxxx-xxxx` 编号
4. 打开 `/admin` → 登录 `operator / operator123` → 反馈审核 → 「采纳生效」
5. 回地图刷新：数据已变；打开「抓取任务」→「触发抓取」→ 任务从 running 变 success

### 4.6 常用命令

| 命令                      | 说明                                                      |
| ------------------------- | --------------------------------------------------------- |
| `pnpm dev`                | 前端开发服务器                                            |
| `pnpm build`              | 类型检查 + 生产构建                                       |
| `pnpm check`              | Lint + 格式 + 类型 + 单测                                 |
| `pnpm e2e`                | Playwright（需 `PLAYWRIGHT_CHANNEL=chrome` 或先装浏览器） |
| `pnpm docs:dev`           | 本文档站                                                  |
| `mvn -DskipTests package` | 后端打包（在 `backend/`）                                 |

### 4.7 常见问题

| 现象                         | 原因                                  | 处理                                                                                 |
| ---------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------ |
| 后台显示「后端未连接」       | 8080 未启动                           | 启动 Spring Boot；前端会自动降级为本地种子数据                                       |
| 抓取任务 502 / 超时          | Overpass 公共实例限流或需代理         | 配置 `HTTP_PROXY`；已配 3 个镜像端点与两段式抓取                                     |
| 抓取任务卡在 running 很久    | 代理 CONNECT 阶段挂起，同步请求不返回 | 已用 `sendAsync + orTimeout` 加硬上限（银行 100s / 小区 120s），超时即失败或 partial |
| 地图瓦片空白                 | 网络无法访问 OSM                      | 自动切换「纯标记模式」，标记位置仍准确                                               |
| 修改了 `schema.sql` 但表没变 | `CREATE TABLE IF NOT EXISTS` 不会加列 | 手工 `ALTER TABLE` 或先 `DROP` 再启动（会丢数据）                                    |
| 登录后立刻 401               | `AUTH_SECRET` 未配置，重启后密钥变了  | 显式设置 `AUTH_SECRET`                                                               |
| 触发抓取返回 409             | 已有任务在跑                          | 等当前任务结束；这是并发保护                                                         |

### 4.8 容器一键部署

```bash
cp .env.deploy.example .env          # 首次：改口令、填 AUTH_SECRET 与 INGEST_PROXY
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
```

Windows 可用封装脚本：`scripts\deploy.ps1`（自动生成 `.env`、等待健康检查）。

端口默认：前端 `8081`、接口 `18080`（仅本机）、MySQL `3307`（仅本机）。
详细步骤、备份恢复与故障排查见 [一键部署（docs/deploy/一键部署.md）](../deploy/一键部署.md)。

> 容器内抓取代理要用 `host.docker.internal:7892`，不能写 `127.0.0.1`。
