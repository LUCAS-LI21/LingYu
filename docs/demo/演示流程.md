# 演示流程方案（评委版 · 约 3 分钟）

> 入口：http://127.0.0.1:8081（Docker 生产形态）；备用：5173（开发）
> 后台：http://127.0.0.1:8081/admin · 账号 `operator`（口令见 `.env`）
> 数据口径：银行 1,874（网点 1,491 + ATM 368 + 新增）、小区 3,569、待定位 4,941

---

## 0. 开场（0:00–0:20）

| 步骤 | 操作                                | 讲解点                                             |
| ---- | ----------------------------------- | -------------------------------------------------- |
| 0.1  | 打开首页，等粒子动画结束（约 7 秒） | 「数据从全球到深圳」的隐喻；可点右上角「跳过动画」 |
| 0.2  | 指针停在顶部导航                    | 地图 / 列表 / 洞察三入口，同一套数据               |

**话术**：邻域 POI 把银行网点和住宅小区从 OSM、政府开放数据、11 家银行官网聚合到一张地图上，并提供从查询到纠错再到重抓的闭环。

---

## 1. 地图查询（0:20–1:10）

| 步骤 | 操作                     | 讲解点                                 |
| ---- | ------------------------ | -------------------------------------- |
| 1.1  | 左侧「图层」勾选「银行」 | 默认 1,491 个网点，白环小点            |
| 1.2  | 「银行类型」切到 ATM     | 368 台自助设备，与网点互斥展示、不拥挤 |
| 1.3  | 点任意 ATM 点位          | 弹窗：名称/地址/营业时间；详情侧栏     |
| 1.4  | 缩放到街道级             | 所有级别同一套标记，不做聚合大圆       |
| 1.5  | 切「彩色 / 卫星」底图    | 三档底图，Esri 源                      |

**话术**：地图是主产品。ATM 与网点互斥，避免上千个点糊在一起；每个点都能点开看到来源。

---

## 2. 小区详情 + 关联查询 + 周边配套（1:10–1:50）

| 步骤 | 操作                       | 讲解点                                                |
| ---- | -------------------------- | ----------------------------------------------------- |
| 2.1  | 图层切「小区」，点任意小区 | 建成年份/成交参考价/物业费，字段级来源可查            |
| 2.2  | 详情下方「周边银行」       | 1km 内银行/ATM，球面距离排序（库内数据）              |
| 2.3  | 点「查 1km 内」→ ATM 开关  | 高德 L2 实时补库内缺口，不落库                        |
| 2.4  | 点「查周边配套」           | 学校/医院/地铁/商场四类计数 + 最近 4 条（L2，不落库） |

**话术**：小区周边配套分两层——可授权落库的银行指标进库；学校医院地铁商场没有可落库授权，走高德实时查询，即取即显、关闭即消失。

---

## 3. 列表 + 排序 + 筛选（1:50–2:20）

| 步骤 | 操作                              | 讲解点                                             |
| ---- | --------------------------------- | -------------------------------------------------- |
| 3.1  | 进入「列表」                      | 默认「数据完整度优先」：地址/价格/年份齐全的排前面 |
| 3.2  | 观察首屏                          | 品牌轮转，同品牌最多连续 2 条，不霸屏              |
| 3.3  | 区域选「南山区」+ 均价「9–11 万」 | 组合筛选，结果数实时变化                           |
| 3.4  | 排序切「均价从高到低」            | 排序 + 分页                                        |

**话术**：完整度排序让第一屏就是「信息最全」的点位；品牌轮转让结果不被单一银行占满。

---

## 4. 洞察（2:20–2:40）

| 步骤 | 操作                 | 讲解点                                               |
| ---- | -------------------- | ---------------------------------------------------- |
| 4.1  | 进入「洞察」         | 银行品牌 Top、小区均价分布（仅官方价样本）、分区对比 |
| 4.2  | 滚到「用户查询热点」 | `query_log → hot_region`，真正的用户行为驱动         |

**话术**：热点不是装饰——定时抓取任务会按 `hot_region.priority` 选网格重抓，形成「查询→热点→补采」闭环。

---

## 5. 反馈闭环（2:40–3:00）

| 步骤 | 操作                   | 讲解点                                            |
| ---- | ---------------------- | ------------------------------------------------- |
| 5.1  | 任意点位 →「提交纠错」 | 填写类型/说明 → 提交                              |
| 5.2  | 得到受理编号 FB…       | 用户可凭编号查状态                                |
| 5.3  | 切后台 →「反馈审核」   | 采纳 → 写 `poi_version` + 字段来源 → 前台立即生效 |

**话术**：反馈不是留言板——审核通过会改主表、记版本、标字段来源；「新增点位」会转成定向 bbox 抓取任务，任务结束回写反馈状态。

## 6. 备用演示（断网/无 Key 时）

| 场景              | 应对                                                                             |
| ----------------- | -------------------------------------------------------------------------------- |
| 后端未起          | 前端自动降级到本地种子（339 条），横幅提示「离线演示」；重启后端 10 秒内自动恢复 |
| 没有高德 Key      | 「实时地址/实时 ATM/周边配套」显示「未配置 AMAP_KEY」，本地库功能不受影响        |
| 没有 DeepSeek Key | 后台 Agent 显示「未启用」，仍可看历史运行记录                                    |
| 数据被改乱        | `docker compose --env-file .env up -d --force-recreate` 重建，启动自动跑迁移     |

## 7. 评委可能追问的点（答案）

1. **为什么 368 台 ATM？** 公开可落库的官方 ATM 只查到平安 212 + 招行 113 + OSM 43；缺口走高德 L2 实时补，不违规落库。
2. **均价为什么只有 1,093 条？** 2021 年官方成交参考价表全量 3,595 个小区，与库内名称匹配上 1,093 条；其余显示「暂无」，不填假值。
3. **服务类型为什么有 1,261 家「未提供」？** 只从官网营业时间文本里提取「对公/对私」，没有证据就不写。
4. **怎么保证抓取合规？** 三级授权（L1 可入库/L2 仅展示/L3 禁用）+ Agent 来源域名白名单（仅银行官网/政府/OSM）。
5. **数据会自己更新吗？** 定时抓取（30 分钟）+ 热点网格优先 + 反馈触发的定向抓取，三条都在跑。
